## 4. How the expected answers were produced
* `backend/evaluation/oracle.py` re-implements every calculation (periods, FIFO debts, overdue, cash-flow rounding, ranking) from the **raw CSV with the standard library only**, sharing no code with the application.
* `tests/test_eval_dataset.py` checks that the application's tools agree with the oracle on every expected figure, date range, evidence id and customer name, for every alternative of every question in **both** sets. A disagreement means a bug in one of them.
* Questions accept several **valid alternatives** (e.g. "compare with last month" may mean the same days or the whole month); a question passes if any alternative is satisfied. Ambiguous questions must be answered with a clarification.
* **Held-out set limitation:** the held-out phrasings were written before the rules mode and not edited after seeing its score, but **the same engineer wrote both**, so it is not an independent sample. The honest test is real merchants' wording and the real model.

## 5. Metric definitions
* **Numerical accuracy**: the final answer states every number (and name) the question requires. A question the system declined to answer counts as a miss.
* **Evidence accuracy**: the tool output itself (before any wording) has the right tool, date range, evidence ids and figures.
* **Traceability**: for answers that need transaction evidence, the evidence contains exactly the expected transaction ids (or is correctly empty for "no data").
* **Unsupported-claim rate (raw)**: how often the model's own wording contained a number the verifier rejected. **(leaked)**: unsupported numbers still present in the answer shown to the user.

### Weaknesses this evaluation found, and what was changed
| Found | Evidence | Fix |
|---|---|---|
| A rounded figure slipped through ("2.0 مليون") because small numbers were allowed as list positions | `round_to_millions` contained 43 / 50 | scaled numbers (مليون/ألف…) are rejected; positional allowance removed |
| A wrong small count passed ("3 زبائن" when it is 7) because the digit existed somewhere in the evidence | `wrong_small_count` contained 0 / 4 | number glued to a counting noun must equal a real count for that noun |
| The model could claim "تم حذف…" after a refused tool call; no number involved | found while writing the suite | action claims and forbidden-tool attempts are replaced by a read-only answer |
| A user-dictated money number could be echoed as a "verified" fact | adversarial question | only small user numbers (days, ids, counts) are trusted |
| "This week vs last week" compared the wrong days | found while designing questions | default comparison bases follow what people mean |
| "علي الجبوري" did not find "علي صباح الجبوري" | found while designing questions | token-based name matching |
| The accuracy metric ignored unanswered questions, which flattered the rules mode (12/12 instead of 12/18) | review of the held-out run | non-answers count as misses; "when answered" reported separately |
| The harness crashed on a provider-outage record | sensitivity test | fixed |
