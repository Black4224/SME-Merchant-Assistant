# Demo script (about 9 minutes)

All figures below were computed by the independent oracle (`backend/evaluation/oracle.py`) and are verified by
`python -m scripts.demo_check`. The demo data is **synthetic**, and "today" is pinned to **Thursday 15 October 2026**: say so.

## Before you go on stage (Windows PowerShell)
```powershell
# terminal 1: backend. Choose ONE of the three assistant modes
cd backend; .venv\Scripts\Activate.ps1
python -m scripts.reset_demo                    # clean demo data
$env:AI_PROVIDER="rules"                        # A) offline mode, no key, no internet (safest)
#   or put GROQ_API_KEY / GROQ_MODEL in ..\.env  # B) real model
#   B + $env:AI_FALLBACK_TO_RULES="true"         # C) real model, drops to rules mode if the network fails
python -m scripts.demo_check                    # must print READY
uvicorn app.main:app --port 8000
# terminal 2: frontend
cd frontend; npm run dev                        # open http://localhost:5173
```
Checklist: browser zoom 110-125 %, fonts loaded, open the app once on a phone-width window,
`data\demo_import_with_errors.csv` and `data\sample_transactions.csv` ready in a folder you can reach from the file dialog.

## The honest scorecard to say out loud
* 513 backend + 119 frontend tests, plus 19 live UI-against-API tests, all passing; the independent oracle and the app agree on every expected figure.
* We tested misbehaving AI models on purpose: 11 kinds of misbehaviour, none reached the user, and the data was never changed.
* CSV import found 15 of 15 injected faults with no false alarms.
* **What we have not yet measured:** accuracy of the real language model on Iraqi dialect (needs the API key; the harness is ready: `python -m evaluation.run --provider groq`).
  Our offline keyword mode, tested on questions we did not tune it on, answered 68 % and declined the rest instead of guessing.

## Questions you may get
| Question | Honest answer |
|---|---|
| "How accurate is the AI?" | "The numbers are computed by Python and checked, not generated by the model. How well the model *understands* dialect is the part we are measuring next; here is the harness and the offline baseline." Do not quote 100 % as AI accuracy. |
| "What if the AI lies?" | Numbers: rejected and replaced (we tested rounding, invented figures, wrong counts). Words: not verified, which is why evidence is always shown. |
| "Where does customer data go?" | With a real model, questions and tool results (including customer names and amounts) go to the provider; descriptions do not. Rules mode stays on the machine. |
| "Can it edit my books?" | No. It is read-only by construction. |
| "Is profit correct?" | "It's an estimate: sales − stock purchases − expenses; no inventory tracking. We say so on screen." |
| "Why not let the model do the arithmetic?" | Because models make arithmetic mistakes confidently; a merchant can't tell. |

## If something breaks
| Symptom | Do this |
|---|---|
| Assistant shows an error / is slow / rate-limited | Restart the backend with `$env:AI_PROVIDER="rules"` (30 seconds). Say so: "offline mode". The 8 example questions all work. |
| Page won't load | Is the backend running? `curl.exe http://localhost:8000/api/health` |
| Numbers differ from this sheet | You changed data: `python -m scripts.reset_demo`, reload the page. |
| Frontend won't start | `cd frontend; npm install; npm run dev` |
| Everything is on fire | Run `python -m scripts.demo_check` and show the READY output + the evaluation report. |
